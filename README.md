# ⚡ AgeCMS

### CMS, которую правят и люди, и ИИ-агенты. Страницы отдаются за 0.2 мс.

PHP 8.1+ и SQLite, без зависимостей, без cron, без сборки. Один каталог, одна команда установки.

## Зачем

Обычная CMS не готова к тому, что сайт правит ИИ-агент: у него нет своего входа, правки не видны, одна ошибка в цикле переписывает сотню страниц, и вернуть всё назад нечем.

AgeCMS сделана под это с первого дня:

- 🤖 **Агент получает доступ сам.** Владелец вставляет в чат одноразовый код, агент читает `/AGENT.md` и работает через MCP со своим токеном и ролью.
- 🧾 **Каждая правка в журнале.** Ревизии с цепочкой SHA-256, которую не изменить даже SQL-запросом. Откат одной кнопкой.
- 🛑 **Предохранитель.** Агент тронул больше 15% страниц за сутки: всё откатывается, запись замораживается, владельцу приходит сообщение в Telegram.
- ⚡ **Скорость статики.** Готовая страница лежит HTML-файлом, nginx или Apache отдают её без PHP.
- 👤 **Человеку тоже удобно.** Вошли в админку, открыли сайт, кликнули по тексту и исправили. Правка идёт в тот же журнал, что и правки агента.

## 🚀 Быстрый старт

### Попробовать на своём компьютере (1 минута)

Нужен только PHP 8.1+ с `pdo_sqlite` и `mbstring`.

```bash
git clone https://github.com/likvp/AgeCMS.git agecms
cd agecms
php bin/requirements.php
php bin/install.php --url=http://127.0.0.1:8000 --name="Мой сайт"
php -S 127.0.0.1:8000 tests/support/router.php
```

Откройте **http://127.0.0.1:8000** (демо-сайт) и **http://127.0.0.1:8000/admin/** (логин `admin`, пароль установщик напечатал один раз, сохраните его сразу).

> `php -S` годится для пробы. На сервере используйте nginx или Apache, как ниже: только тогда теневой кэш отдаётся без PHP.

### Поставить на сервер (nginx или Apache)

**1. Скачайте и проверьте среду.**

```bash
git clone https://github.com/likvp/AgeCMS.git /var/www/agecms
cd /var/www/agecms
php bin/requirements.php
```

Команда перечисляет, чего не хватает, и в каждой строке пишет, как поставить. Для Debian и Ubuntu всё рекомендуемое ставится одной строкой (подставьте свою версию PHP):

```bash
apt install php8.3-fpm php8.3-sqlite3 php8.3-mbstring php8.3-gd php8.3-curl php8.3-zip
```

Повторяйте `php bin/requirements.php`, пока не увидите «Всё необходимое есть».

**2. Установите сайт.**

```bash
php bin/install.php --url=https://example.com --name="Мой сайт"
```

Создаются база в `data/`, ключ подписей, демо-страницы и администратор. Пароль печатается один раз. Флаги: `--admin=имя`, `--password=...`, `--no-demo` (пустой сайт), `--strict` (не ставить без рекомендуемых расширений).

**3. Отдайте каталог пользователю PHP.**

```bash
chown -R www-data:www-data /var/www/agecms
```

Не открывайте `0777`. Пользователь PHP должен быть владельцем каталога, иначе не будут работать загрузка картинок и кнопка «Обновить».

**4. Настройте веб-сервер.**

- **nginx:** скопируйте [nginx.vhost.example](nginx.vhost.example) в `/etc/nginx/sites-available/`, поправьте `server_name`, `root` и сокет PHP-FPM, включите сайт и выполните `nginx -t && systemctl reload nginx`.
- **Apache:** [.htaccess](.htaccess) из корня работает сам. Нужны `mod_rewrite`, `mod_headers` и `AllowOverride All`.

**5. Войдите в `/admin/` и смените пароль.** В разделе «Система», блок «Требования сервера», видно, каких расширений не хватает именно PHP веб-сервера: он бывает другим, чем в консоли.

Готово. Cron не нужен: очередь, кэш и пинги поисковикам обрабатываются сами после сохранения и при заходах посетителей.

### Хостинг без SSH

1. Загрузите файлы по FTP в корень сайта.
2. Положите в `data/install.key` любую случайную строку от 32 символов.
3. Откройте `https://ваш-сайт/admin/install.php?key=<эта строка>`: мастер из трёх шагов проверит среду, спросит название и покажет пароль один раз.

После установки появляется `data/install.lock`, и установщик закрывается навсегда.

### Поручить установку ИИ-агенту

Скажите агенту с доступом к серверу:

```text
Поставь AgeCMS из https://github.com/likvp/AgeCMS на этот сервер по инструкции AGENTS.md, адрес сайта https://example.com
```

В [AGENTS.md](AGENTS.md) расписан порядок: проверка среды, установка всех расширений, права, веб-сервер и что сообщить владельцу в конце.

## ✨ Возможности

| | Что | Как устроено |
| :---: | --- | --- |
| ⚡ | **Shadow Cache** | Страница лежит файлом `assets/cache/<slug>.html`, веб-сервер отдаёт её сам. Без настройки сервера работает быстрый путь в первых строках `index.php`. |
| ✍️ | **Dual-UX** | Правка кликом по тексту на живой странице и редактор блоков с перетаскиванием. Люди и агенты пишут в одну очередь и один журнал. |
| 🤖 | **MCP-шлюз** | `POST /admin/mcp.php`, JSON-RPC 2.0, Bearer-токен, роли. Инструкция для агента отдаётся по адресу `/AGENT.md` с адресом сайта внутри. |
| 🧾 | **Неизменяемая история** | Ревизии как патчи RFC 6902, контрольные снимки, цепочка SHA-256, триггеры SQLite запрещают менять и удалять ревизии. Откат создаёт новую ревизию. Туда же пишутся обновления ядра, пользователи, токены, модули, бэкапы. |
| 🛑 | **Предохранитель** | Больше 15% страниц (и не меньше 3) за скользящие сутки на токен: транзакция откатывается, запись замораживается до `bin/unfreeze.php`, уведомление в Telegram. |
| 🧩 | **Схема блоков** | Тема объявляет типы блоков и поля. Всё, что не подходит под схему, отклоняется до записи в базу. |
| 📦 | **Подписанные модули** | Папка с `manifest.json` и подписью Ed25519. Подмена любого файла блокирует модуль. Навыки модуля видны агенту как инструменты `<модуль>__<навык>`. |
| 🔄 | **Обновление одной кнопкой** | Пакеты ядра подписаны дважды (Ed25519 и ECDSA P-256), хватает одной верной подписи. Откат к прежней версии: `php bin/update.php --rollback` или агентом через API. |
| 🔎 | **SEO из коробки** | meta, canonical, JSON-LD (FAQ, хлебные крошки), `sitemap.xml`, `robots.txt`, `llms.txt`, IndexNow, 301 при смене адреса, полнотекстовый поиск FTS5. |
| 🔐 | **Безопасность** | Двухфакторный вход (TOTP), CSRF, лимиты входа, токены только хэшем, защита от SSRF, антиспам форм (подписанный токен времени, honeypot, лимиты по IP). |
| 💾 | **Бэкап** | Целостный снимок базы (`VACUUM INTO`), ротация, отправка в Telegram, автоматическая копия перед первой правкой агента. |
| 🖼️ | **Медиа** | Сжатие в WebP и AVIF, медиатека, корзина для страниц и картинок. |

## 🤖 Подключить ИИ-агента

**Самый простой путь.** В админке, раздел «Система», кнопка «Получить текст для агента». Получится готовый текст с адресом сайта и одноразовым кодом `agi_...` (действует сутки). Вставьте его в чат с агентом. Агент прочитает `https://example.com/AGENT.md` и сам обменяет код на токен:

```bash
curl -s https://example.com/admin/api.php -H "Content-Type: application/json" \
  -d '{"action":"redeem_invite","code":"agi_...","name":"claude-seo"}'
```

**Через консоль.** Выдайте токен и проверьте шлюз:

```bash
php bin/token.php create seo-agent --role=editor
curl -s https://example.com/admin/mcp.php \
  -H "Authorization: Bearer agc_..." -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Для MCP-клиентов адрес и заголовок те же.

<details>
<summary><b>Подробнее: сроки токенов, роли, вход по паролю</b></summary>

<br>

- Токен живёт ограниченный срок (`agent_access.token_days`, по умолчанию 90 дней). За неделю до конца приходит предупреждение в заголовке `X-AgeCMS-Token-Warning` и в `get_site_structure`.
- Пользователя можно заблокировать: его вход и токены перестают работать.
- Перед первой правкой агента за сеанс делается копия базы (`backup.before_agent`, хранятся последние `backup.keep_auto`).
- Запасной путь: владелец даёт агенту логин и пароль, сайт заводит агенту отдельного пользователя `agent-<имя>` и выдаёт токен на него (`"own_user": false` отключает это). Адрес `/AGENT.md` указан и в `/llms.txt`, и в ответах 401.

```bash
curl -s https://example.com/admin/api.php -H "Content-Type: application/json" \
  -d '{"action":"issue_token","username":"anna","password":"...","name":"claude-seo","role":"editor"}'
```

- Роль токена не выше роли пользователя, неверные пароли считаются как при входе в админку, не больше 10 токенов в час на пользователя.
- Пользователю с двухфакторным входом токен по паролю не выдаётся, только по коду подключения.
- Владелец видит и отзывает токены в «Системе», там же выключается самовыдача (`agent_access.self_issue` в `data/config.php`).

</details>

## 📊 Тесты и замеры

Главная страница демо-сайта, полный рендер против попадания в теневой кэш:

| Сервер | Режим | req/s | Медиана |
| --- | --- | ---: | ---: |
| nginx + php-fpm, VPS на 2 ядра | полный рендер | 232 | 3.72 мс |
| nginx + php-fpm, VPS на 2 ядра | **кэш, отдаёт nginx** | **3 350** | **0.20 мс** |
| Apache + php-fpm, Apple M5 Pro | полный рендер | 1 392 | 0.72 мс |
| Apache + php-fpm, Apple M5 Pro | **кэш, отдаёт Apache** | **9 019** | **0.11 мс** |

На слабом сервере кэш быстрее в 14 раз. Методика, параллельные замеры и то, что не измерялось: [docs/BENCHMARK.md](docs/BENCHMARK.md).

```bash
php tests/run.php                    # все тесты, песочница во временной папке
php bench/shadow_cache_bench.php     # замер на своей машине
```

Тесты проходят на PHP 8.1, 8.2, 8.3, 8.4 и 8.5 (`bin/test-matrix.sh` гоняет 8.1-8.4 в Docker). Покрыты журнал и триггеры, предохранитель, параллельные писатели, схема, кэш, подписи модулей и обновлений, защита от SSRF, антиспам, установка и сквозной HTTP-прогон.

## 🛠 Команды

| Команда | Что делает |
| --- | --- |
| `php bin/requirements.php [--json] [--strict]` | проверить среду (код 0: всё есть, 1: нет обязательного, 2: нет рекомендуемого) |
| `php bin/install.php --url=... [--name=...]` | установить сайт |
| `php bin/token.php create <имя> --role=editor` | выдать токен агенту (показывается один раз, в базе только хэш) |
| `php bin/token.php list` / `revoke <имя>` | список и отзыв токенов |
| `php bin/unfreeze.php` | снять заморозку после срабатывания предохранителя |
| `php bin/verify-chain.php` | проверить цепочку хэшей ревизий |
| `php bin/clear-cache.php` / `rebuild-cache.php` | сбросить и пересобрать кэш |
| `php bin/backup.php [--telegram]` | снимок базы |
| `php bin/config.php get\|set <ключ> [значение]` | настройки и секреты (`secrets.telegram_bot_token`, `secrets.telegram_chat_id`, `updates.url`) |
| `php bin/sign-module.php <модуль>` | подписать модуль после правки |
| `php bin/update.php [--install\|--rollback]` | проверить, поставить новую версию ядра или вернуть прежнюю |
| `php bin/queue-worker.php` | разобрать очередь вручную (необязательно, всё работает и без cron) |

Ежедневный бэкап по расписанию: `0 3 * * * php /var/www/agecms/bin/backup.php` (или кнопка «Сделать бэкап» в «Системе»).

## 📋 Требования

| | Расширение | Зачем |
| :---: | --- | --- |
| ✅ обязательно | PHP 8.1+, `pdo_sqlite` с FTS5, `mbstring`, `json` | ядро, база, поиск |
| ⭐ рекомендуется | `sodium`, `openssl` | подписи обновлений и модулей, 2FA, SMTP |
| ⭐ рекомендуется | `gd` с WebP | сжатие картинок |
| ⭐ рекомендуется | `curl`, `zip`, `zlib` | Telegram, IndexNow, вебхуки, бэкапы, модули архивом |

Без рекомендуемых расширений сайт ставится и работает, но соответствующие возможности выключены. `php bin/requirements.php` скажет точно.
