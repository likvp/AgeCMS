📐 Архитектурный Манифест и Техническое ТЗ: AgeCMS (by Tabson.ru)
Версия документа: 2.0 (Full Architectural & Product Blueprint) Статус: Базовый документ разработки (Master Reference Document for Humans & AI Agents) Концепция: Universal, Safe, Frictionless & Agent-Native PHP/SQLite CMS Главный слоган: «Умное упрощение: 1-ms скорость, абсолютная безопасность и понятность как для человека, так и для ИИ-агента»
📋 1. Обзор продукта и Стратегическое Позиционирование
AgeCMS — это компактная, высокопроизводительная и полностью автономная система управления контентом (CMS) нового поколения. Она разработана с учетом параллельного использования двумя типами пользователей (Dual-UX):

1. Люди (Владельцы бизнеса, контент-менеджеры, веб-мастера): Управляют сайтом через визуальный интуитивный интерфейс (Bento UI / contenteditable) без знания кода.
2. ИИ-агенты (Cursor, Claude, Windsurf, Custom LLM Runners): Взаимодействуют с сайтом либо через файл инструкций AGENT.md, либо через протокол MCP (Model Context Protocol) / JSON-RPC.

Ключевая ценность (The "Golden Key"):

* Zero-Setup & Zero-Lockin: Вся система запускается копированием файлов по FTP. База данных — один файл (data.sqlite).
* Мгновенная миграция (60-Second Migration): ИИ-агент спарсит любой старый сайт (WordPress, Tilda, Bitrix) и за 1 минуту перенесет его структуру, тексты и медиа в AgeCMS.
* 1-ms Скорость (Shadow Cache): Публичные страницы отдаются напрямую веб-сервером (Nginx / Apache) или ультрабыстрым PHP-фальбэком, не нагружая сервер и базу данных.
* Защита от сноса кода: Понятное «устройство дома», где ИИ-агенту не нужно переписывать систему, так как его роли и границы четко зафиксированы.

🏗️ 2. Технический стек и Архитектура ядра
Технологический стек:

* Язык: PHP 8.1+ (строгая типизация ядра, минимальное количество зависимостей).
* СУБД: SQLite 3 (в режиме WAL — Write-Ahead Logging).
* Фронтенд и Админка: HTML5, Tailwind CSS (Bento UI паттерн), Alpine.js.
* Кэширование: Static Flat-File Shadow Cache (/assets/cache/*.html).

Структура каталогов системы:
```
/
├── AGENT.md                      # Инструкция и правила поведения для ИИ-агентов
├── HOSTER_INTEGRATION_WHITEPAPER.md # Стандарт интеграции для хостинг-провайдеров
├── index.php                     # Единая точка входа (Router + Fallback Cache)
├── .htaccess                     # Правила маршрутизации и кэширования Apache
├── nginx.vhost.example           # Пример идеального конфига для Nginx / VPS
├── core/                         # Ядро системы (Незаменяемый каркас)
│   ├── Database.php              # Singleton PDO SQLite + WAL + Lock Queue
│   ├── Router.php                # Роутинг динамических страниц
│   ├── Cache.php                 # Генерация и инвалидация Shadow Cache
│   ├── Security.php              # Circuit Breaker, HMAC-подписи, RBAC
│   └── SkillRegistry.php         # Загрузка и проверка валидности скилов
├── data/                         # Пользовательские данные (Изолированный контур)
│   ├── data.sqlite               # Основная БД (Страницы, конфиги, ревизии)
│   ├── logs/                     # Structured JSON logs (mcp_agent.json)
│   └── queue/                    # Очередь фоновых задач для параллельных агентов
├── assets/
│   └── cache/                    # Сгенерированный статический HTML (Shadow Cache)
├── modules/                      # Модули расширения (Module-as-a-Skill)
│   └── <module_name>/
│       ├── skills/               # JSON/MD схемы для MCP-агентов
│       └── Module.php            # Логика модуля
└── themes/                       # Bento UI шаблоны
    └── default/
```

⚡ 3. Производительность: 3-Уровневая система «1–2 мс» (Shadow Cache)
Генерация страниц происходит в момент сохранения контента (off-request Static Site Generation). На запрос пользователя сервер отдает готовую статику.
```
[ Запрос пользователя: GET /services/repair ]
                     │
                     ▼
        ┌─────────────────────────┐
        │ 1. Nginx (try_files)    │ ──(Нашел /assets/cache/repair.html)──► [0.8–1.5 мс] (PHP не просыпается)
        └────────────┬────────────┘
                     │ (Кэша нет / Apache)
                     ▼
        ┌─────────────────────────┐
        │ 2. Apache (.htaccess)   │ ──(Перенаправил на /assets/cache/)──► [1.0–2.0 мс] (PHP не просыпается)
        └────────────┬────────────┘
                     │ (Гибридный / Простой хостинг)
                     ▼
        ┌─────────────────────────┐
        │ 3. index.php (Fallback) │ ──(file_exists check в 1 строчке)──► [1.5–3.0 мс] (Окончание без СУБД)
        └────────────┬────────────┘
                     │ (Первичный рендер / Динамика)
                     ▼
        ┌─────────────────────────┐
        │ 4. Full PHP Runtime     │ ──(Подключение SQLite, рендер)──────► [15–30 мс]
        └─────────────────────────┘
```

Таг-базированная Инвалидация Кэша (Tag-Based Invalidation):
Во избежание полной пересборки тысяч файлов при изменении шапки/футера:

1. Каждая сгенерированная страница привязывается к мета-тегам (tags: ["global_header", "page_123"]).
2. При изменении сквозного блока в очередь инвалидации попадают только затронутые страницы, обновляемые фоновым скриптом.

🔒 4. Безопасность, Мультиагентность и Защита от сноса
A. Взаимодействие с SQLite при мультиагентности (Concurrency & Write Lock)
Чтобы несколько ИИ-агентов (SEO, Content, Migrator) не упирались в ошибку SQLITE_BUSY:

1. BEGIN IMMEDIATE TRANSACTION: Избегаем дэдлоков при старте записи.
2. Single-Writer Queue (Mutex / File Lock): Агенты не пишут в БД напрямую параллельно. Изменения ставятся в очередь (/data/queue/*.json) и последовательно обрабатываются локальным воркером.

B. Неизменяемый аудит ревизий (Time-Travel Ledger)

* Все изменения сохраняются в таблице revisions.
* Таблица защищена встроенными SQLite-триггерами (BEFORE UPDATE / DELETE), которые блокируют попытку изменить историю даже с правами администратора (Append-Only Ledger).
* Сжатие данных (Diff-based): Во избежание распухания базы сохраняется не весь дамп Bento UI, а JSON Patch (RFC 6902) изменений. Старые ревизии архивируются по политике Pruning Policy.

C. Предохранитель массовых правок (Circuit Breaker)
Если агент попытается сломать сайт или внести галлюцинаторные правки:

* Если отдельная операция затрагивает >15% общего объема страниц базы за одну сессию, транзакция автоматически абортится (RuntimeException).
* База замораживается, админу уходит уведомление, а состояние откатывается на 1 шаг назад.

D. Защита SKILL-файлов (Supply Chain Attack Protection)

* Все исполнительные инструкции и MCP-схемы в /modules/<name>/skills/ подписываются цифровой подписью HMAC / RSA Public Key.
* При попытке подмены .json или .md файла без валидного ключа SkillRegistry.php блокирует исполнение навыка.

E. Безопасность установки (Zero-Setup without Race Condition)

* Никаких уязвимых автоинициализаций через первый веб-запрос (First-Request-Wins).
* Установка выполняется через CLI (php bin/install.php) либо с созданием случайного 32-значного ключа установки в data/install.lock.

🤖 5. Dual-UX: Взаимодействие человека и ИИ-агента
ЧЕЛОВЕЧЕСКИЙ УРОВЕНЬ (Human Layer):

* Bento UI: Модульная верстка на базе фреймворка Tailwind CSS и легких скриптов Alpine.js.
* In-Context Editing (contenteditable): Правка текста прямо на странице сайта "глазами клиента".
* Защищенные каркасы: Пользователь не может сломать адаптивность и стилистику сайта, меняя лишь контентные сущности внутри жестких блоков.

ИИ-УРОВЕНЬ (Agent Layer & AGENT.md):
Файл AGENT.md в корне сайта — это "Конструкция Дома" для ИИ.
Пример структуры AGENT.md:
```
# AGE_CMS_AGENT_INSTRUCTIONS

## Роль и Границы
Ты — автономный администратор этого сайта. 
Твоя задача: наполнять контент, оптимизировать SEO, проводить миграции.

## Правила проекта:
1. КОД ЯДРА: Папка `/core/` НЕПОДВИЖНА. Не пытайся переписать `index.php` или `Database.php`.
2. ДАННЫЕ: Вся информация хранится в SQLite `/data/data.sqlite`.
3. СКИЛЛЫ: Для работы используй модуль MCP-шлюза (`/admin/mcp.php`) или JSON-RPC команды.
4. КЭШ: После любых изменений структуры вызови CLI-команду `php bin/clear-cache.php`.
```

💼 6. Бизнес-модель, Партнерства и Коммерциализация
1. Монетизация токенов (AI API Proxy & Gateway)
Заработок без собственного агента:

* Whitelabel API Proxy: Перепродажа единого API-ключа для доступа к OpenAI, Claude, DeepSeek, YandexGPT со своей маржой (+30–100%).
* Фиксированная подписка на AI-контент: Тариф «3000 руб/мес за 500 AI-генераций» (себестоимость токенов ~200-300 руб).
* Семантическое кэширование (Semantic Cache): Повторные типы запросов к ИИ от разных клиентов отдаются из локального кеша, экономя до 90% затрат на API-токены.

2. Партнерство с РФ IT-гигантами (Яндекс, Сбер, VK, Хостинг-провайдеры)

* Яндекс / Сбер: Внедрение AgeCMS как B2B-драйвера потребления токенов YandexGPT / GigaChat и облачных ресурсов Yandex Cloud / SberCloud.
* Программы грантов: Вход в программы Yandex Cloud Boost / AI Studio Boost (получение грантов на 500k-1M+ руб. в токенах).
* Хостеры (Beget, Reg.ru, Timeweb): Внедрение стандарта HOSTER_INTEGRATION_WHITEPAPER.md. Экономия ресурсов серверов хостеров, отсутствие нагрузок от MySQL, включение AgeCMS в 1-Click маркетплейсы панелей управления.
