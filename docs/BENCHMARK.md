# Замеры теневого кэша

Измерено 27.10.2026 на одной машине: Apple M5 Pro, 18 ядер, macOS, PHP 8.5.7 (opcache по умолчанию), SQLite 3.53. Клиент и сервер на одном хосте через loopback, поэтому сети в цифрах нет. Страница: главная демо-сайта, 6924 байта.

Что измерялось: главная страница двумя способами.

- Полный рендер: запрос `/?n=1`. Строка запроса отключает кэш, поэтому выполняются PHP, SQLite и шаблоны темы.
- Попадание в кэш: запрос `/`. Готовый файл `assets/cache/index.html` отдаёт веб-сервер, PHP не запускается.

## Apache 2.4.67 + php-fpm 8.5.7 (8 процессов), `ab -k`, настоящий `.htaccess` из репозитория

| Режим | Запросов | Параллельность | req/s | Среднее на запрос |
|---|---|---|---|---|
| Полный рендер | 5000 | 1 | 1392 | 0.72 мс |
| Попадание в кэш | 5000 | 1 | 9019 | 0.11 мс |
| Полный рендер | 20000 | 32 | 9294 | p50 3 мс, p95 4 мс, p99 5 мс |
| Попадание в кэш | 20000 | 32 | 13350 | p50 2 мс, p95 3 мс |

Вывод: при одном соединении страница из кэша в 6.5 раза быстрее полного рендера и укладывается в целевую 1 мс (0.11 мс). При 32 соединениях разница сжимается до 1.4 раза, потому что `ab` на той же машине упирается в собственный процессор, а PHP-рендер на M5 Pro с opcache и локальным SQLite сам занимает меньше миллисекунды. На слабом хостинге с общим диском рендер дороже, и выигрыш будет заметно больше. Эту часть я не измерял.

## `php -S` (4 воркера), `bench/shadow_cache_bench.php`, клиент на `curl_multi`

| Режим | req/s | p50 | p95 | p99 |
|---|---|---|---|---|
| Полный рендер | 6772 | 4.40 мс | 6.09 мс | 7.56 мс |
| Кэш через быстрый путь в `index.php` | 20628 | 1.16 мс | 2.11 мс | 4.85 мс |

Вывод: даже без настройки веб-сервера (запасной путь, PHP стартует, но не грузит фреймворк и базу) выигрыш 3 раза по запросам в секунду.

## Не измерялось

- nginx: на машине его нет, `nginx.vhost.example` проверен только чтением.
- Нагрузка на слабом VPS и на общем хостинге.
- Холодный старт после перезапуска php-fpm.
- Большие сайты (тысячи страниц, сотни тысяч ревизий). Цепочка хэшей проверяется целиком командой `bin/verify-chain.php`, её время на больших журналах не замерялось.

## Как повторить

```bash
php bench/shadow_cache_bench.php 3000 32                      # свой php -S во временной папке
php bench/shadow_cache_bench.php 3000 32 http://127.0.0.1:8089  # уже работающий Apache или nginx с установленным сайтом
ab -n 5000 -c 1 -k http://127.0.0.1:8089/
```

Если `ab -k` показывает несколько «Failed requests: Length», это особенность `ab` с keep-alive: при проверке `curl_multi` 6000 параллельных запросов все ответы побайтно одинаковы, а `ab` без `-k` ошибок не даёт.
