# AGE_CMS_AGENT_INSTRUCTIONS

Ты администратор этого сайта. Сайт работает на AgeCMS (PHP + SQLite). Твоя работа: наполнять контент, улучшать SEO, переносить старые сайты. Систему менять не нужно, у неё есть фиксированные границы.

Адрес сайта: {{SITE_URL}}. Эта инструкция лежит по адресу {{SITE_URL}}/AGENT.md и доступна без входа, файловая система сервера тебе не нужна: всё делается через веб.

## Как получить доступ

Тебе нужен токен (строка вида `agc_...`). Есть три способа, по убыванию удобства для владельца. Если ничего из этого у тебя нет, сначала попроси владельца: «Откройте в админке раздел „Система“, нажмите „Получить текст для агента“ и пришлите мне его». Это одна кнопка, пароль владельца не нужен.

1. **Готовый токен `agc_...`.** Владелец дал его сам: пропусти этот раздел и сразу подключайся.
2. **Одноразовый код подключения `agi_...`.** Лучший вариант, пароли не передаются:

```
POST {{SITE_URL}}/admin/api.php
Content-Type: application/json

{"action": "redeem_invite", "code": "agi_...", "name": "<твоё имя>"}
```

3. **Логин и пароль пользователя.** Если владелец дал их, запроси токен: сайт сам заведёт для тебя отдельного пользователя (`agent-<твоё имя>`, с твоей ролью и паролем, которого никто не знает), и токен будет принадлежать ему, а не владельцу. Дальше ты работаешь от своего пользователя, и владелец может заблокировать его, не трогая свою учётную запись. Основной пароль владельца после этого не нужен. Пароль без необходимости не проси; если нужен токен без своего пользователя, добавь `"own_user": false`:

```
POST {{SITE_URL}}/admin/api.php
Content-Type: application/json

{"action": "issue_token", "username": "<логин>", "password": "<пароль>", "name": "<твоё имя>", "role": "editor"}
```

Ответ на способы 2 и 3: `{"ok": true, "result": {"token": "agc_...", "role": "editor", "user": "agent-<имя>" (при способе 3), "expires_at": "...", "mcp": "...", "rest": "...", "instructions": "..."}}`.

- Токен показывается один раз. Сохрани его у себя (в памяти или секретах агента) и дальше работай только с ним. Пароль и код после этого не нужны: не храни их и не записывай в контент сайта.
- `name`: 2-40 знаков, латиница, цифры и `_ . -`, должно быть свободно (например `claude-seo`). Роль токена не выше роли пользователя; для кода роль задал владелец.
- У токена есть срок (по умолчанию 90 дней, `expires_at`). Его видно в ответе `get_site_structure` в поле `token` (`days_left`, `warning`). За неделю до конца в ответах приходит заголовок `X-AgeCMS-Token-Warning`: скажи владельцу заранее, что нужен новый код. В `issue_token` можно попросить срок короче: поле `days`.
- Пять неверных паролей подряд блокируют вход на 15 минут, 10 неверных кодов в час блокируют адрес. Ошибка `self_issue_disabled` значит, что владелец закрыл выдачу по паролю: попроси код или токен. Ошибка `two_factor` значит, что у этого пользователя включён вход с кодом из приложения: по одному паролю токен не выдаётся, попроси у владельца одноразовый код подключения. Ответы `401` с текстом `blocked` или `expired` значат, что пользователя заблокировали или токен истёк.
- Владелец видит твой токен в разделе «Система», видит когда ты обращался, и может отозвать токен в любой момент.
- Для работы тебе не нужен ни FTP, ни SSH, ни доступ к коду: всё, что нужно для сайта, есть в инструментах ниже. Если кажется, что без кода не обойтись, скажи владельцу, что именно не получается.

## Как подключиться

- Точка входа: `POST {{SITE_URL}}/admin/mcp.php`, JSON-RPC 2.0, заголовок `Authorization: Bearer <токен>`.
- Поддерживаются стандартные методы MCP (`initialize`, `tools/list`, `tools/call`) и прямые имена инструментов (`{"jsonrpc":"2.0","method":"get_site_structure","id":1}`).
- Если твоя среда не умеет JSON-RPC, используй простой вариант: `POST {{SITE_URL}}/admin/api.php` с телом `{"action": "<инструмент>", ...аргументы}` и тем же заголовком.

## Порядок работы

1. Вызови `get_site_structure`: страницы, меню, настройки, **типы блоков темы с допустимыми полями**, состояние заморозки, версия ядра (`core.version`; если `core.newer` не пустое, вышла новая версия, скажи об этом владельцу). С токеном admin ядро можно обновить: `check_core_update` (что нового и можно ли поставить), `update_core` (ставит только подписанный пакет, перед этим копия базы и старых файлов), `rollback_core` (вернуть прежние файлы), `set_core_updates` (адрес проверки и автообновление). Перед `update_core` спроси владельца.
2. Читай страницу через `get_page`, не угадывай структуру.
3. Правь точечно: `update_block_field` для одного поля, `update_block_data` для блока, `update_page` для метаданных. Структуру страницы меняй операциями над блоками, а не заменой всего списка `blocks` (так не затрутся чужие правки): `add_block` (`type`, `after`: id блока, за которым встанет новый, `""` в начало, без `after` в конец; без `data` обязательные поля заполнятся подписями, блок с обязательной картинкой требует `data`; в ответе `block_id`), `move_block` (`block_id`, `after`), `duplicate_block`, `delete_block` (блок остаётся в истории).
4. Новые страницы: `create_page` (`slug` и `fields` с `title` и `blocks`; пример: `{"action":"create_page","slug":"remont-kvartir","fields":{"title":"Ремонт квартир","blocks":[...]}}`). Адрес делай из заголовка латиницей через дефисы. Все поля страницы (`title`, `blocks`, `meta_title`, `is_published` и остальные) лежат **внутри `fields`**, рядом со `slug` они не читаются, и такой вызов вернёт ошибку. Чтобы страница не показывалась посетителям, пока не готова, передай `"fields": {"is_published": false, ...}` сразу при создании и включи её позже через `update_page` (`"fields": {"is_published": true}`). Минимальная страница: `{"action":"create_page","slug":"garantiya","fields":{"title":"Гарантия","blocks":[{"id":"intro","type":"text","data":{"heading":"Гарантия","body":"Текст."}}]}}`; у каждого блока свой `id` (латиница, цифры и `_`, с буквы); допустимые типы блоков и их поля бери из `get_site_structure`. Ответ `create_page` не говорит, опубликована ли страница: проверь через `get_page`. Много страниц: `batch_create_pages` (до 100 за вызов).
5. Сменить адрес страницы: `rename_page` (`slug`, `new_slug`). Со старого адреса остаётся постоянный редирект 301, пункты меню обновляются, дочерние страницы сохраняют свои адреса и остаются вложенными. Главной страницей так распорядиться нельзя.
6. Правка оказалась ошибкой: `list_revisions`, затем `rollback_revision`. Откат это новая ревизия, история не стирается. Страницу можно удалить через `delete_page` (главную и страницу с дочерними нельзя): она попадает в корзину, вернуть её можно через `list_deleted_pages` и `restore_page`. Окончательное удаление из корзины агентам недоступно, его делает администратор в админке.

## Границы

| Что | Правило |
| --- | --- |
| Код | Папки `core/`, `admin/`, `bin/`, файлы `index.php`, `.htaccess` неподвижны. Ты работаешь только через инструменты. |
| Данные | Контент и настройки хранит сайт, напрямую к хранилищу ты не обращаешься и путь к нему не ищешь. Всё читается и пишется только через инструменты. |
| Структура | Страница это метаполя и список блоков `{id, type, data}`. Неизвестный тип блока, неизвестное поле, слишком длинный текст, HTML в тексте, `javascript:` в ссылке отклоняются. |
| Текст | Только обычный текст. Абзацы в поле `text` разделяются пустой строкой. |
| Роли | `viewer` читает, `editor` читает и пишет контент, `admin` ещё настройки и токены. Ошибка `forbidden` значит, что роли не хватает. |
| Копия базы | Перед твоей первой правкой за сеанс система сама делает копию базы (последние пять хранятся). Ошибку можно откатить через ревизии, а в крайнем случае владелец восстановит копию. |
| Скорость записи | Записи идут через очередь по одной. Это нормально: ответ придёт после применения. |
| Лимит запросов | 120 вызовов в минуту на токен. |
| Предохранитель | Если за сутки (скользящие 24 часа, считается по вашему токену, смена часа или сеанса счётчик не обнуляет) изменено больше 15% существующих страниц (и не меньше 3), последняя правка откатывается и запись замораживается. Ошибки `circuit_breaker` и `frozen` значат: остановись и сообщи администратору. Разморозить может только человек: кнопка в админке или `php bin/unfreeze.php`. |
| Новые страницы | Считаются отдельно, лимит 500 за сессию. Перенос сайта возможен. |
| Кэш | После правок кэш сбрасывается сам, только у затронутых страниц. Ручной сброс `clear_cache` почти никогда не нужен. |
| Модули | Инструменты модулей имеют вид `<модуль>__<навык>`. С токеном admin можно ставить свои модули: `install_module` (файлы текстом или zip), `list_modules`, `disable_module`, `enable_module`, `delete_module` (формат в docs/MODULES.md ядра). Модуль без подписи работает сразу, владелец видит его красным; подписывает модуль только человек в админке. Перед установкой расскажи владельцу, что делает код. Подпись и файлы чужих модулей не меняй. |
| Секреты | Токены, пароли и ключи тебе не показываются. Не проси их и не записывай в контент. |

## Хорошая практика

- Перед массовой работой напиши администратору план: какие страницы затронешь.
- Делай `get_page` после записи, если от результата зависит следующий шаг.
- Для SEO: у каждой страницы заполни `meta_title` (до 200 знаков) и `meta_description` (до 500), `schema_type` по смыслу страницы. FAQ-блок автоматически даёт разметку FAQPage.
- Картинки: файл можно отправить на `POST {{SITE_URL}}/admin/upload.php` (multipart, поле `file`, Bearer-токен), либо `import_image` скачает публичную картинку по https, сожмёт в WebP и вернёт путь `/assets/uploads/...` для полей `og_image` и url.
